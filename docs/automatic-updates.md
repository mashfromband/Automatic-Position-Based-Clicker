# 自動更新と復元

デスクトップの「Multi Point Clicker」は、アプリを開く前にこのリポジトリの最新の安定リリースを確認します。
プレビュー版は使いません。
更新先は公開リリースのWindows実行ファイルに限定し、GitHubが記録するSHA-256とサイズが一致した場合だけ使用します。
通信処理は非表示の子プロセスで行い、最新版の確認は最大4秒、新しい本体の取得は別に最大15秒とします。
上限を超えたら手元の版を開きます。
端末のウィンドウやログイン画面は表示しません。

## アプリと設定を一緒に戻す

更新前の実行ファイルとアプリデータは、同じ組み合わせとして残します。
新版にはアプリデータ全体のコピーを渡すため、新版が設定を書き換えても、旧版のデータには影響しません。
正常な起動を確認できるまで、使用中の版を指す記録は切り替えません。

新版の設定読み込み・ウィンドウ作成・初期コントロールの作成・メッセージ処理が完了すると、起動確認を返します。
起動確認と短い継続動作を確認してから新版へ切り替えます。
次の場合は旧版と旧データへ戻して開きます。

- 新版の実行ファイルを起動できない。
- 設定の読み込みや移行に失敗する。
- 起動確認前に異常終了する、または8秒以内に起動確認が返らない。
- 更新の起動確認から60秒以内に異常終了する。
- 次回の起動時に、使用中の実行ファイルの破損やアプリデータの欠落を検知する。

起動失敗はプロセス終了を検知してから復元し、応答しない場合は8秒を上限として終了します。
起動後しばらく正常に使えていた版の異常終了では、使用中の設定を保持してエラーを表示し、次回も同じ版を使います。
明らかに起動に失敗した版と同じ実行ファイルは、次回の起動で繰り返し適用しません。
負荷による一時的な起動遅延を区別するため、起動確認の時間切れだけは次回に1回再試行し、2回続いたら適用を止めます。
更新中に起動用のプロセス自体が終了した場合も、次回は未確認の更新を取り消して旧版を開きます。
アプリは生成時からWindowsのジョブに所属させるため、起動用のプロセスが終了しても、未確認のアプリだけが残って起動を妨げることはありません。
アプリがまだ動いている場合は、そのアプリを表示し、更新や設定の切り替えを行いません。
復元先まで起動できない場合は、繰り返し起動せずエラーを表示します。
保存していた設定が消え、復元先にも設定が残っていない場合は、初期設定で上書きせずエラーを表示します。
初回コピーや両方の切り替え記録の読み込みに失敗した場合も、導入時に保存した旧版があれば、従来の設定でその旧版を開きます。

## 保存場所

`%LOCALAPPDATA%\MultiPointClicker` に次のファイルを保存します。

| 場所 | 内容 |
| --- | --- |
| `Multi Point Clicker.exe` | 起動と更新を行う固定の実行ファイル |
| `versions\<版とハッシュ>\multi-point-clicker.exe` | 版ごとのアプリ本体 |
| `data\<識別子>\MultiPointClicker` | 版と組み合わせて保持する設定・バックアップ |
| `state.json` | 現在の版、復元先、確認中の更新 |
| `state-backup.json` | 直前の有効な切り替え記録 |
| `update-status.json` | 最後の通信失敗や復元の理由 |

初回に従来の `%APPDATA%\MultiPointClicker` をコピーします。
設定以外のバックアップも一緒に引き継ぎ、元のフォルダーは変更しません。
復元元・復元先のデータと、失敗した版のデータは別々に残します。
起動確認用の一時フォルダーは確認後に削除し、不要になった旧実行ファイルは、復元に必要な版と初回の退避版を残して整理します。
版ごとの設定データは、変更を失わず取り出せるように保持します。
更新後に追加した設定は、復元後の旧データに混ぜません。

起動用の実行ファイルは処理中・アプリ使用中だけ動き、アプリの終了とともに終了します。
アプリを常時監視するサービスや定期タスクは作成しません。

## 配布する版の作り方

`Cargo.toml` の版を上げた変更を `main` に取り込むと、Windowsのテスト・Clippy・リリースビルドの成功後に、同じ版のGitHubリリースを作成します。
実行ファイルと初回用ZIPを非公開のドラフトへアップロードしてから公開し、未完成の更新を配布しません。
同じ版が公開済みの場合は上書きしません。
公開処理は直列にし、すでに公開済みの版より古い版を最新として選び直すことはありません。
将来のアプリ本体も、起動確認の形式を維持してください。
起動用の実行ファイルは、使用中の実行ファイルを上書きしないため固定し、必要な改修時はアプリが終了している状態で配布ZIPから置き換えます。

## 検証

設定を変更してから失敗する子プロセスを用い、旧版が元の設定で起動することを確認します。
起動しない子プロセス、応答しない子プロセス、別の起動確認を返す子プロセス、破損した実行ファイル、途中終了からの再開も検証します。
これらのテストは一時フォルダーと非表示の検証用プロセスを使い、実デスクトップにクリックしません。
