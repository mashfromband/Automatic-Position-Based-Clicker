# キーで仮想コントローラーをクリックする

画面上の仮想コントローラーを、WASDなどのキーからクリックできます。
キーを1回押すと、そのキーに記憶した場所を1回だけクリックします。
押し続けた場合の自動リピートではクリックを増やさず、一度離して押し直すと次の1回を送ります。
連打ロックの切り替えとは別の操作です。

## WASDの登録例

1. 「キーでクリック」タブを開き、「ゲーム画面を選ぶ」を押します。
2. ツールが隠れたら対象のゲーム画面をクリックします。Escで取り消せます。
3. 「WASDを追加」を押します。
4. Wの「位置を記憶」を押し、仮想十字キーの上をクリックします。
5. 同じようにAに左、Sに下、Dに右の位置を記憶します。
6. 「キー操作を有効にする」をオンにし、ゲームを前面にして操作します。

| キー | クリックする仮想ボタン |
| --- | --- |
| W | 上 |
| A | 左 |
| S | 下 |
| D | 右 |

ゲーム画面とクリック位置を選ぶときだけツールを隠し、記憶すると設定画面へ戻ります。
実際のキー操作ではツールを前面へ出しません。
クリック後にマウスポインターを操作前の場所へ戻します。
ゲームが入力を読み取れるよう、ボタンを50ミリ秒押し、離した位置でも50ミリ秒待ってからマウスを戻します。
これは1回のクリックの保持時間で、長押し連打には変わりません。
この約0.1秒の処理中に手でマウスを動かした場合も、最後はクリック開始前の位置へ戻します。

## 別のキー・左右クリック

「＋ 追加」で空の行を追加できます。最大16キーです。
行のキーボタンを押し、割り当てたいキーを押して離すと保存します。
文字、数字、矢印、スペース、Enter、ファンクションキーなど、単独のキーを使えます。
Escは割り当ての取り消しに使います。Ctrl・Alt・Shift・Winを押している間はクリックへの変換を行わず、通常のショートカットを優先します。
同じキーを2行へ割り当てたり、既存の操作用キーと重複させたりすると、元の割り当てを保持します。
左クリックと右クリックは行ごとに選べます。

キーと位置は自動で保存します。
ゲーム名・実行ファイルのパス・ウィンドウクラスは位置と一緒に保存します。HWNDやプロセスハンドルなど実行中の識別子は保存せず、ツールを開き直したら「ゲーム画面を選ぶ」で対象を選択し直します。
保存したキーと位置は残ります。

## 動作する範囲

- 選んだゲームウィンドウが前面のときだけキーをクリックへ変換します。
- 別のアプリへ切り替えると通常のキーボード入力になります。
- ゲーム終了後に別のプロセスへ入力を送らないよう、選択したプロセスのハンドルとウィンドウを保持して確認します。
- ウィンドウを移動しても、ゲーム内の同じ位置をクリックします。
- ゲーム画面の大きさを変えると登録位置が無効になるため、各行で位置を記憶し直してください。
- 通常の連打や位置の記録中は、一時的にキー操作を止めます。
- 「設定」の停止キー（初期値 `Ctrl+Alt+X`）はキー操作も停止します。現在の停止キーはこのタブにも表示します。停止キーを登録できない場合は有効化しません。再開するときは「キー操作を有効にする」をオンにします。
- `Ctrl+Alt+L` の連打ロックは従来どおりです。

Chrome、Edge、Firefoxなど一般的なブラウザーを対象にした場合は、タブの見出しが変わった際も入力を止めます。
通常のゲームでは、同じウィンドウの見出しが変わっても操作を続けます。

## 検証

キーの押下・リピート・解放、複数キー、対象外に相当するキー状態、注入されたイベント、設定変更後の古い要求を、純粋な状態処理と送信先の差し替えでテストします。
押下・解放・マウス復帰を別々に送り、ゲームが押した状態と離した状態を読み取れる時間を確保します。
停止や画面の切り替えを検知した場合は待機を中断し、開始済みのボタンを解放してマウスを戻します。
押下と解放の送信後に停止した場合も、送信済みの1回はクリック数に加算します。
Windowsが入力を継続して拒否している場合は、解放や復帰の再試行にも失敗することがあるため、エラーを表示します。
250ミリ秒より古くなった待機中のキー入力は破棄し、操作後に古いクリックを長く再生し続けないようにします。
20・30・60・120・240Hzでマウス状態と位置を読む仮想のゲームを使い、押下と解放の両方が観測されることを位相を変えて確認します。
テストでは送信先を差し替え、非表示の専用コントロールで保存と画面の切り替えを確認し、実デスクトップへクリックは送りません。
実際のゲームのフォーカス判定、プロセス識別、フックスレッドと実入力の組み合わせは、自動で実ゲームを操作した検証には含みません。
