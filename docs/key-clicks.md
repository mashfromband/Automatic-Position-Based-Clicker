# WASDで画面の方向ボタンやスティックを操作する

画面上の仮想コントローラーへWASDなどのキーを割り当て、1回のクリック、押している間の保持、スティックの操作を選べます。
ゲームごとに位置と操作方法を保存し、一覧から切り替えられます。
これは「メイン」の自動クリックや連打ロックとは別の操作です。

## WASDの登録例

1. 「キーでクリック」タブで新しいゲーム別設定を作ります。
2. 「ゲーム画面を選ぶ」を押し、対象のゲーム画面をクリックします。Escで取り消せます。
3. 「方向ボタン」と、ゲームが受け付ける入力方法を選びます。
4. Wの「位置を記憶」を押し、画面上の上ボタンを指定します。
5. 同じようにAに左、Sに下、Dに右を指定し、各行の動作を選びます。使わない方向は未登録のままにできます。
6. 設定名を付けて「保存」し、「キー操作を有効にする」をオンにします。
7. ゲームを前面にして操作します。

| キー | 割り当てる方向 |
| --- | --- |
| W | 上 |
| A | 左 |
| S | 下 |
| D | 右 |

ゲーム画面とクリック位置を選ぶときだけツールを隠し、記憶すると設定画面へ戻ります。
実際のキー操作ではツールを前面へ出しません。
「1回クリック」は1回の押下につき1回だけ送り、キーの自動リピートでは増やしません。
既定の押下・解放時間はそれぞれ50ミリ秒です。
マウスの1回クリックが重なった場合は順番に送りますが、250ミリ秒を過ぎた操作は破棄します。
同じキーを解放後の50ミリ秒以内に押し直した場合は、そのクリックを後から再生しません。
マウス方式では操作前の位置への復帰を行いますが、手でマウスを操作した場合はその操作を優先します。

「押している間」はキーを押した状態で入力を保持し、離すと解放します。連打は行いません。
W+Dは右上、W+Aは左上です。W+SとA+Dは反対方向を相殺します。
複数の場所を独立して保持するには、ゲームがタッチ入力に対応している必要があります。

## スティック

移動方式を「スティック」にし、「中心を記憶」で画面上のスティックの中心を指定します。
移動幅は中心から動かす距離です（初期80px、4〜2048px）。中心と動かす範囲はゲーム画面の内側へ収めてください。
WASDを押している間はその方向へ動かし、すべて離すと解除します。
このモードでは、保存してあるWASDの方向ボタン割当は発火させず、ほかの追加キーは残します。
方向ボタン用の位置は、方式を戻したときに使えるよう保持します。

## タッチとマウス

タッチ方式は、ゲームが受け付ける場合に複数の接点を使って移動と追加操作を同時に送ります。
マウス方式は1本のポインターを使うため、別の位置を独立して同時に押すことはできません。
実現できない組み合わせは警告し、保持を壊して追加クリックを送ったり、後から古い操作を再生したりはしません。
ゲームが合成入力を受け付けない場合は操作が反映されないため、方式ごとの反応を確認してください。

タッチの保持は、Windowsの[タッチ入力API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-injecttouchinput)の押下・更新・解放として扱います。
APIで入力を送れたことと、ゲームがその操作を読み取ったことは別です。

## 別のキー・左右クリック

「＋ 追加」で空の行を追加できます。最大16キーです。
行のキーボタンを押し、割り当てたいキーを押して離します。操作名は任意で入力できます。
文字、数字、矢印、Space、Shift、Enter、ファンクションキーなどを使えます。
Escは割り当ての取り消しに使います。Ctrl・Alt・Winを含む通常のショートカットは優先します。
以前のマウスの1回クリックだけの設定では、Shiftを含むショートカット優先も保持します。長押し・スティック・タッチ・Shift割当ではShiftとの併用を扱います。
同じキーを2行へ割り当てたり、既存の操作用キーと重複させたりすると、元の割り当てを保持します。
左クリックと右クリックは行ごとに選べます。
タッチ方式では右クリックを送れないため、右クリックを使う設定ではマウス方式を選んでください。
Shiftを含む停止キーなど、登録済みの操作用ショートカットと一致する組み合わせは、ゲームへの変換より優先します。

## ゲームごとの設定

「保存」で設定名を確定し、一覧から選んで切り替えます。「新規」で新しい設定を作れます。
切替時は現在の編集を保持してキー操作をオフにし、ゲーム画面を選び直すよう案内します。
「削除」は確認後に選んだ設定だけを削除します。
保存できる設定は64件までです。上限では新規作成を止め、現在の編集を保持します。
未保存の設定を編集中に「削除」を押すと、削除する保存済み設定を一覧から選べます。
ゲーム名・実行ファイルのパス・ウィンドウクラスは位置と一緒に保存しますが、HWNDやプロセスハンドルなど実行中の識別子は保存しません。
ツールを開き直したときも対象画面を選び直します。保存したキーと位置は残ります。

v3設定は原本をバックアップしてv4へ移行します。既存の間隔・キー・左右クリックと、従来の1回クリックは保持します。

## 動作する範囲

- 選んだゲームウィンドウが前面のときだけキーをクリックへ変換します。
- 別のアプリへ切り替えると通常のキーボード入力になります。
- ゲーム終了後に別のプロセスへ入力を送らないよう、選択したプロセスのハンドルとウィンドウを保持して確認します。
- ウィンドウを移動しても、ゲーム内の同じ位置をクリックします。
- ゲーム画面の大きさを変えると登録位置が無効になるため、各行で位置を記憶し直してください。
- 通常の連打や位置の記録中は、一時的にキー操作を止めます。
- 「設定」の停止キー（初期値 `Ctrl+Alt+X`）はキー操作も停止します。現在の停止キーはこのタブにも表示します。停止キーを登録できない場合は有効化しません。再開するときは「キー操作を有効にする」をオンにします。
- `Ctrl+Alt+L` の連打ロックは従来どおりです。

Chrome、Edge、Firefoxなど一般的なブラウザーを対象にした場合は、タブの見出しが変わった際も入力を止めます。
通常のゲームでは、同じウィンドウの見出しが変わっても操作を続けます。

## 検証

キーの押下・リピート・解放、複数キー、方向の相殺、追加操作、対象外のキー状態、注入イベント、設定変更後の古い要求を、実際の入力状態処理と送信先の差し替えでテストします。
タッチ接点の押下・継続更新・解放と、マウスの押下・解放・復帰を区別して確認します。
停止や画面の切り替えを検知した場合は待機を中断し、開始済みのボタンを解放してマウスを戻します。
登録位置が一時的に隠れた場合などは、キーを離して押し直すことで再開できます。
入力送信や監視の失敗で停止した場合は有効化もオフにし、エラーを表示します。
押下と解放の送信後に停止した場合も、送信済みの1回はクリック数に加算します。
Windowsが入力を継続して拒否している場合は、解放や復帰の再試行にも失敗することがあるため、エラーを表示します。
250ミリ秒より古くなった待機中のキー入力は破棄し、操作後に古いクリックを長く再生し続けないようにします。
従来の1回クリックでは、20・30・60・120・240Hzでマウス状態と位置を読む仮想のゲームを使い、押下と解放の両方が観測されることを位相を変えて確認します。
テストでは送信先を差し替え、非表示の専用コントロールで保存と画面の切り替えを確認し、実デスクトップへクリックは送りません。
実際のゲームのフォーカス判定、プロセス識別、フックスレッドと実入力の組み合わせは、自動で実ゲームを操作した検証には含みません。
