# Rust版の仕様

Multi Point ClickerをWindows用のRustアプリへ移行する。
既存の画面構成・日英切替・ライト/ダーク・10か所記録・位置プレビュー・設定保存・グローバルショートカットを維持する。

- 共通間隔は初期値0.501秒、最小0.0000001秒、最大3600.0000000秒とし、小数点以下7桁まで入力できる。
- 間隔は浮動小数ではなく100ns単位の整数で保存する。0、8桁以上の小数、NaN、指数表記、範囲外は拒否し、直前の設定を保持する。旧Rust版のミリ秒は10000倍して変換し、元ファイルを保全する。
- 「詳細設定」は開閉できる。開閉自体では個別設定の有効/無効を変えない。
- 個別設定の有効時は、各行の間隔がそのクリック位置から次の位置までの待機時間になる。最後の行は次の周回の先頭へ適用する。有限回の最終クリック後は待たない。
- 個別の値は位置と一緒に保持し、位置の削除時にも対応をずらさない。個別指定を無効にしたら共通間隔を使い、個別の値は消さない。
- Windowsの高分解能WaitableTimerを使う独立スレッドでクリックし、最後の最大150µsだけ短いスピンで補う。GUIの50msの更新周期はクリック間隔に影響させない。OSが高分解能タイマーを提供しない場合は通常タイマーを使う。記録用マウスhookは記録中のみ、キーhookはキー割り当て中のみ使う。
- 停止キー/停止ボタンは開始待機中・長いクリック間隔の待機中でも中断し、停止完了後に追加クリックしない。
- 初回移行では旧settings.jsonをsettings.python-backup.jsonとして保全し、クリック位置・周回数・キー等を引き継ぐ。初回の共通間隔は本人指定の0.501秒にする。以後はユーザーが保存した間隔を保持する。
- 壊れた設定を未作成と混同しない。読み込めなければエラーを表示して設定を上書きしない。
- コンソールを表示しないWindows実行ファイルを配布し、既存のショートカットを更新する。

100nsは指定できる最小間隔であり、Windowsの負荷や対象アプリの処理にかかわらず厳密な100nsや毎秒1000万回の処理完了を保証するものではない。
タイマー自体の測定と、専用の検証用ウィンドウが実際に受信したクリックの測定を分ける。
